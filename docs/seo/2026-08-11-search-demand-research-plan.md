# Keyly Google 曝光研究與 SEO 優化計畫

更新日期：2026-08-11  
市場：台灣／繁體中文  
主要目標：Google 非品牌自然搜尋日曝光超過 100

> **狀態（2026-08-11）**：研究已完成，四項交付物齊備。第一名為**首頁 `iPhone 注音` 主題群優化**（既有頁優化，不新增頁面），brief 見 [首頁 iPhone 注音主題群 SEO 優化 Brief](content-brief-homepage-iphone-zhuyin.md)，已實作完成、等待部署。打字速度測試工具已降級為候補，不平行開發。

## 核心問題

台灣使用者有哪些與 iPhone 鍵盤、繁中輸入、注音選字及 AI 寫作相關的搜尋需求，具備足夠的曝光規模，而且 Keyly 有合理機會進入搜尋結果前段？

## 決策目標

研究只需要支持一個決定：**下一個應優化哪個搜尋主題群，以及應採用既有頁優化、新頁、互動工具、影片或原創資料中的哪一種形式。**

在研究完成前，不預設要寫 Guide，也不把監測、Schema、PageSpeed 或文件整理當成曝光成長策略。

## 已知條件與限制

- 網站的 robots、sitemap、canonical、hreflang、SSR 與主要內部連結沒有已知封鎖性問題。
- 五篇繁中 Guide 已部署並要求建立索引，但上線時間短，尚不足以判定成效。
- GSC 歷史基準顯示整體曝光低、可見 query 以品牌字為主。
- 不購買廣告、關鍵字工具、連結或媒體合作；可使用 GSC、GA4、Google Trends、Google 搜尋結果及免費平台。
- Keyly 的實際能力包括繁中注音、全拼、雙拼、小鶴雙拼與 AI 文字功能；不包含自己的手寫或語音功能。
- 不得捏造搜尋量、排名、競品流量或轉換率。

## 最大不確定性

目前最大的未知不是「網站還能寫什麼」，而是：

1. 哪些主題群真的有足夠的台灣搜尋需求？
2. 搜尋結果是否允許一個新 App 官網以實用資產或專業內容競爭？
3. 哪些需求最接近 Keyly 的產品價值及下載意圖？

只要這三項足以區分候選機會，研究就停止，不做無限延伸。

## 研究流程

### 第一階段：建立曝光基準

從 GSC 取得最近 90 天、28 天與 7 天資料，維度至少包含 query、page、country、device、date：

- 台灣總曝光、點擊、CTR、平均排名。
- 品牌 query 與非品牌 query 分開計算。
- 已有曝光的頁面與查詢配對。
- 排名 8–30、可能透過優化推進的查詢。
- 新 Guide 只標記索引及早期曝光，不用短期數字判定成敗。

產出：`GSC 現況基準表`。若 query 因資料量太低而被隱藏，必須明確標記資料不足。

### 第二階段：建立搜尋需求全集

候選詞不得只從腦力激盪產生，至少交叉使用以下來源：

1. GSC 已有 query 與相近詞。
2. Google 自動完成、相關搜尋、People Also Ask 與實際 SERP 標題。
3. Google Trends 的台灣相對趨勢；只能判斷相對熱度，不能當成絕對搜尋量。
4. App Store 描述、使用者問題與 Keyly 已上線功能。
5. 主要競品在 Google 已取得排名的頁面與主題。

先建立下列種子主題，但允許證據推翻或新增：

- iPhone 鍵盤／第三方鍵盤選擇。
- 注音選字、錯字、自動選字及輸入效率。
- 全拼、雙拼、小鶴雙拼與繁體中文輸入。
- Apple Intelligence、AI 寫作、Email／社群文字處理。
- 完全取用、隱私、離線及權限疑慮。
- 手機中文打字速度、正確率及練習工具。

產出：去重後的 `關鍵字群 × 搜尋意圖` 清單，不為每個關鍵字建立一頁。

### 第三階段：判斷需求與競爭機會

每個主題群抽取代表性查詢，檢查台灣行動版 SERP 前 10 名：

- 結果類型：官方文件、媒體、論壇、影片、工具、App Store 或產品頁。
- 搜尋意圖：了解、排錯、比較、操作、工具使用或下載。
- 結果是否陳舊、內容是否不完整、是否缺少繁中／iPhone／實測資料。
- 前 10 名網域強度及頁面品質；不能只以網域大小判斷無法競爭。
- Google 是否偏好影片、圖片、工具或一般文字頁。
- Keyly 能提供的獨特證據：實機畫面、產品能力、664 句 benchmark 或互動功能。

產出：每個主題群一列 `SERP 缺口與可勝出理由`。沒有具體缺口者淘汰。

### 第四階段：量化排序

每個候選主題群以 100 分評估：

| 指標 | 權重 | 判斷依據 |
|---|---:|---|
| 需求證據 | 30 | GSC 曝光、Trends 相對熱度、SERP／建議詞廣度；沒有數據就降低信心 |
| 產品關聯 | 25 | Keyly 是否真的解決該需求，且功能已上線 |
| 可競爭性 | 20 | SERP 是否存在內容、工具、時效或繁中缺口 |
| 下載意圖 | 15 | 搜尋者解決問題後是否可能需要第三方鍵盤 |
| 零成本可執行性 | 10 | 能否用既有程式、資料、裝置與免費平台完成 |

淘汰條件：

- 必須虛構產品能力或無法證實的比較。
- 搜尋意圖與 Keyly 無直接關聯。
- SERP 被官方答案完全滿足，Keyly 沒有新增價值。
- 只能靠大量相似薄頁取得覆蓋。
- 需要付費資料、後端服務或推廣才能成立。

產出：附證據與信心等級的 `SEO 機會排行榜`，不是主觀題目清單。

### 第五階段：頁面與資產對應

排名前三的機會，先選最符合 SERP 的形式：

| SERP／需求特徵 | 優先形式 |
|---|---|
| 現有 Keyly 頁已排名 8–30 | 優化原頁，不新增頁面 |
| 使用者需要完成測試或計算 | 互動工具 |
| 操作過程比文字更容易理解 | 實機影片＋必要的網站影片頁 |
| Keyly 擁有別人沒有的量測結果 | 原創研究／benchmark |
| 意圖明確且現有頁完全無法承接 | 新增一個獨立頁面 |

每個主題群只能有一個主要承接頁，避免關鍵字互相競爭。

### 第六階段：選出第一個曝光實驗

第一名必須同時具備：

- 有需求證據，而不是只看到一個自動完成詞。
- 有具體 SERP 缺口及 Keyly 可提供的差異。
- 可以零額外現金成本完成。
- 能設定單一主要頁面與可辨識的 GA4 事件。
- 預期能為「日曝光 100」貢獻可說明的一部分；不要求單頁獨自承擔全部目標。

只為第一名產出 MVP brief，再交由 Claude 實作。第二、三名保留為候補，不平行開發。

**已完成（2026-08-11）**：第一名選定為首頁 `iPhone 注音` 主題群優化，MVP brief 已產出並完成實作。打字速度測試工具因 Trends 相對熱度為 0 且既有工具成熟而降級為候補。

## 驗證與迭代

- 上線前：確認初始 HTML、索引資格、主要意圖、事件與內部入口。
- 第 7、14 天：只確認索引、查詢是否出現及曝光方向。
- 第 28 天：比較上線前後的 page × query 曝光、排名與點擊。
- 有曝光且排名 8–30：優化同頁的標題、首段、內容缺口與內鏈。
- 已有前段排名但 CTR 低：調整搜尋標題與摘要。
- 無曝光：重新檢查需求與索引，不直接複製更多頁面。
- 曝光增加但下載點擊為零：再處理意圖與轉換，不把它誤判為曝光失敗。
