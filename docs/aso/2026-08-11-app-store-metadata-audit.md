# Keyly 免費 ASO Metadata 稽核

更新日期：2026-08-11

> 第一輪變更（副標題、關鍵字、Support URL）的完整 before/after 與長度檢查，見 [ASO Metadata 變更記錄 — 第一輪](2026-08-11-metadata-change-round-1.md)。三項阻擋事項已於 2026-08-11 裁決完畢，關鍵字定案為 41 字元／99 bytes；三個欄位已於 2026-08-11 上傳至 1.1.1，尚未送審。

## 決策

目前最值得做的免費 ASO 工作不是重寫整份商店文案，而是先修正隱藏關鍵字的相關性與欄位分工，再把支援網址統一到正式網域。名稱保留；副標題與宣傳文字只做一輪可回復的 MVP 測試。

本報告不使用付費 ASO 工具，也沒有搜尋量或競品排名數據，因此不得把建議詞稱為「高流量關鍵字」。

產品端於 2026-08-11 確認：Keyly 沒有自己的手寫功能、沒有自己的語音輸入功能；全拼、微軟雙拼與小鶴雙拼都已在正式版 1.1.0 開放。

## Apple 官方規則

- App 名稱與副標題各最多 30 個字元。
- 關鍵字欄位最多 100 bytes；Apple 建議用逗號分隔、不加空格，避免重複字、類別名稱、`app`、特殊符號與不相關詞。
- 不得在關鍵字中不當使用商標、競品名稱或與產品無關的詞。
- App 可由名稱、副標題、關鍵字與公司名稱被搜尋。
- 宣傳文字不影響 App Store 搜尋排名，應用於最新功能或轉換訊息，而不是堆關鍵字。
- Description 會出現在產品頁，也可能用於公開網頁搜尋結果；它不是本輪 App Store 關鍵字排序的首要控制項。

## 高信心問題

### P1：關鍵字含待確認或不相關功能

目前有 `手寫`、`語音輸入`。產品端已確認 Keyly 沒有自己的手寫與語音輸入功能。

處理方式：下一版 metadata 必須移除。不能因 iOS 系統可能提供相關能力，就把它當成 Keyly 功能關鍵字。

### P1：`ChatGPT` 與 `Threads` 有商標及相關性風險

目前關鍵字使用 `ChatGPT` 與 `Threads文案`。Apple 明確警告不要不當使用受保護詞或其他產品名稱。Keyly 的公開文案描述為雲端 AI，沒有把 ChatGPT 列為正式整合品牌；`Threads` 只是使用情境。

MVP 建議：隱藏關鍵字移除兩者，改用功能型用語。**2026-08-11 定案採用 `社群貼文` 取代 `Threads文案`**；`ChatGPT` 直接移除，本輪未以其他詞遞補（欄位空間優先給 1.1.0 的輸入方案功能詞）。

### P1：新版本可搜尋功能沒有進入索引欄位

1.1.0 promotional text 與 What's New 已公開寫出全拼、微軟雙拼、小鶴雙拼，但目前名稱、副標題及關鍵字都沒有這些詞。產品端已確認三項均在正式版 1.1.0 開放；Apple 明確說 promotional text 不影響搜尋排名。

MVP 建議：把 `全拼輸入`、`雙拼輸入`、`小鶴雙拼` 放入關鍵字欄位。這是功能相關性判斷，不代表已證實有高搜尋量。

**2026-08-11 裁決**：本輪採增量修正，不重置整個欄位——保留仍然成立的既有詞，只換掉不實、重複或有商標風險的部分。不使用單獨的 `微軟`。`微軟` 是 Microsoft 的中文公司名稱，與本報告移除 `ChatGPT`、`Threads文案` 所引用的是同一條 Apple 規則（不得使用其他 App 或公司名稱）；改以 `雙拼輸入` 承接一般雙拼意圖。同時所有詞改用四字組合，確保每個關鍵字都超過 2 個字元，符合 Apple 對關鍵字長度的要求。

### P2：副標題重複名稱中的 `AI`

名稱已包含 `AI`，副標題再次使用 `AI`，同時把有限空間用在「高階」與「零側錄」等較不像搜尋任務的詞。Apple 建議避免重複字，副標題則應補充產品價值或使用情境。

測試候選：

`文章潤飾、語氣改寫與即時翻譯`

這個版本不重複名稱中的 Keyly、AI、注音、輸入法、鍵盤，且只描述正式 description 已列出的能力。它不是唯一正解；上線後需用 App Store Analytics 比較產品頁轉換。

### P2：Support URL 仍指向預覽網域

目前為 `https://keyly-website.pages.dev/#faq`，Marketing URL 與隱私政策則已使用 `keylyapp.com`。這不一定影響排名，但會造成品牌與支援入口不一致。

建議改為 `https://keylyapp.com/#faq`；送出前先確認錨點在正式站有效。

### P2：宣傳文字堆疊形容詞，隱私說法過度絕對

現行文字包含「重磅、強大、極致、零側錄」等大量宣傳詞。宣傳文字不影響搜尋排名，應優先讓訪客快速理解 1.1.0 新功能與資料處理界線。

保守候選：

> 全新字典引擎與全拼、微軟雙拼、小鶴雙拼現已上線。直接在鍵盤內使用 AI 潤飾、翻譯與語氣調整；日常輸入在裝置端處理，只有主動使用線上 AI 時才傳送所選文字。

上線前須確認「只有主動使用線上 AI 時才傳送所選文字」與目前產品、第三方 SDK 及隱私政策完全一致。

## 截圖與轉換資料限制

- 本輪沒有可用的視覺瀏覽器，因此未對商店截圖做目視驗收。
- 尚未取得 App Store Analytics 的搜尋曝光、產品頁瀏覽與首次下載漏斗，因此不能斷言目前轉換率差，也不能證明哪個關鍵字帶量。
- 截圖與漏斗資料必須分開研究，不應用 metadata 猜測代替。

## 執行與驗證

1. 產品端已完成三項輸入功能確認；送出前再核對隱私文字與正式 FAQ 錨點。
2. Claude 只準備 metadata 變更文件或 App Store Connect 操作清單，不直接送審，交由 Codex Review。
3. 第一輪只改副標題、關鍵字與 Support URL；名稱、宣傳文字、description、截圖與圖示保持不變。
4. **變更必須填入下一個可編輯並送審的 App Store 版本，不是已上線的 1.1.0。**本輪的套用版本為 `1.1.1`（使用者於 2026-08-11 回報已建立）；填入前先確認該版本仍可編輯。往後每一輪都要重新確認當時的可編輯版本，不要沿用舊版本號，也不要假設下一版必然是接續的修補版。
5. 變更時記錄日期、**實際套用的版本號**與完整 before/after，一次只做這一組。
6. 該版本上架後至少觀察 14–28 天 App Store Analytics：App Store Search impressions、product page views、first-time downloads 與 conversion rate。
7. 資料量太小時，只記錄，不宣布勝負；不要因一兩天波動反覆改 metadata。

## 不做的事

- 不購買 ASO 工具或關鍵字量。
- 不使用競品名稱、買量或激勵評論。
- 不把公開 App Store 搜尋頁快取當成正式 metadata。
- 不同時改名稱、圖示、截圖、價格與 onboarding，避免無法判斷原因。
